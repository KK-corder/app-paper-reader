# ブリーフ: 今日の一本と PDF を入れる流れ（段階 2）

> 種別: 機能追加。Claude が作成し Codex に渡す実装仕様。

- **プロジェクト**: `/Users/kakeru/Dev/4_アプリ/PaperReader`
- **出典**: 要件 `/Users/kakeru/Dev/_system/docs/20261028-論文リーダー-今日の一本要件.md`（§2 と §6 の「決定」）。Mac 側との取り決め `/Users/kakeru/Dev/_system/docs/20261028-論文リーダー-フィード書き出し要件.md`（**§2 の `feed` の形と §3 の `feed_log.json` の形がアプリとの取り決め**。必ず読む）。本人 2026-10-28: 週の表示は「PDF を入れた日だけ」を数える／メモ欄は次のブリーフに分ける
- **委任設定**: effort=`high` / model=既定（初めて PDF をドライブに入れる。大きなファイルのアップロード・権限・端末内の表示の重ね合わせが絡むため）

## 目的

毎朝フィードが選んだ論文を、アプリの一覧の一番上に要約つきで出す。本人が Safari で PDF をダウンロードし、アプリの「PDF を入れる」で選ぶと、アプリがドライブの `survey/` に入れ、その場で左に PDF・右に要約で読める。これを毎日の習慣にする。

## 作るもの（WHAT）

### 1. 一覧の一番上の枠

- `papers.json` の `feed`（新しい日が先）を、今までの一覧（`papers`）の**上に別の枠として**出す。今までの一覧・絞り込み・検索とは混ぜない（絞り込みや検索をしても、この枠はそのまま）
- **今日の一本**: `feed` の先頭で `served` が今日（日本時間）のもの。カードに、題・掲載先・年・著者・`ja`（見出し「これは何の論文か」）・`why`（見出し「あなたにとっての意味」）・アブストラクト（たたんでおき、押すと開く）・DOI のリンク（`https://doi.org/<doi>`）を出す。空の項目は出さない
  - PDF がまだなら、ボタン「PDF を取ってくる」と「PDF を入れる」と「見送る」
  - PDF が入っていれば（`pdf` がある・この端末で入れた）、ボタン「読む」
- **PDF 待ち**: 今日以外の `feed` のうち、PDF が無く見送ってもいないもの。今日の一本の下に、題と `served` の日付と「PDF を取ってくる」「PDF を入れる」「見送る」を 1 行ずつ（行を押すとカードと同じ中身を開いてよい）。0 件なら見出しごと出さない
- `feed` が無い・空のときは、この枠を出さない（今の papers.json でも落ちない）
- 枠の上か下に小さく「この 7 日で PDF を入れた日 n/7」。数え方は下の §4。強い色・通知・罰のような演出はしない

### 2. PDF を取ってくる

- `oa_pdf` があればそれを、無ければ `https://doi.org/<doi>`、それも無ければ `url` を、新しいタブ（`target="_blank"`・`rel="noopener"`）で開く。どれも無ければボタンを出さない
- `oa_pdf` が無い論文には、ボタンの横に小さく「学内ネットワーク／VPN で開く」と添える

### 3. PDF を入れる

1. `<input type="file" accept="application/pdf">` で選ばせる（iPhone では「ファイル」から選べる）
2. 先頭 5 バイトが `%PDF-` でなければ「PDF ではないようです」と出して止める
3. `survey/` の直下に、`feed[].pdf_name` と**同じ名前のファイルがすでにあれば、アップロードせず**そのファイルを使う（上書きしない）
4. 無ければ Drive API v3 の**再開可能アップロード**で入れる: `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=resumable`（メタデータ `{name: pdf_name, parents: [survey の ID], mimeType: "application/pdf"}`）→ 返った `Location` に `PUT` で中身。進み具合を「アップロード中 n%」のように出す（`fetch` で進み具合が取れなければ、送信中の表示だけでよい）。名前は `pdf_name` をそのまま使い、アプリで作らない
5. 入ったら、`_reader/feed_log.json` に `{"key", "action": "pdf", "at", "name", "drive_id"}` を追記する（Mac 側の要件 §3。作り方は `reading_log.json` と同じ: 無ければ `_reader/` の中に作る、あれば読んで足して同じ ID に PATCH、壊れていたら上書きしない）
6. そのまま**読む画面を開く**。左はいま入れた PDF（ファイル ID で開く）、右の要約タブは `ja`・`why`・アブストラクトを見出しつきで、基本情報タブは題・著者・掲載先・年・DOI。読了ボタンは出さない（論文DB にまだ無いため）。`notion_id` があって `papers` にその論文があれば、普通の論文として開く

- 失敗したとき:
  - 通信の失敗・ログイン切れ: 「アップロードできませんでした」と出し、選び直してもう一度押せるようにする（PDF の中身は端末に残さなくてよい）
  - **403・404（`drive.file` の権限で `survey/` に書けない）**: 「アプリから survey に入れられませんでした。iPhone の『ファイル』で、ダウンロードした PDF を Google ドライブの survey フォルダへ『<pdf_name>』の名前で移してください」と出し、`pdf_name` をコピーするボタンを付ける（本人の手で入れる道に切り替える）
- `feed_log.json` の追記だけ失敗したら、記録を端末に残して送り直す（読了の記録と同じ仕組み・同じタイミング。設定画面の「未送信の記録: n 件」にも数える）

### 4. 見送る・この 7 日の表示

- 「見送る」で `{"key", "action": "skip", "at"}` を追記し、その論文を PDF 待ちから外す。今日の一本を見送ったら、カードは小さくたたんで「見送り済み・取り消す」を出す。「取り消す」で `unskip` を追記して戻す
- 「この 7 日で PDF を入れた日 n/7」: 今日を含む直近 7 日（日本時間）のうち、`action: "pdf"` の記録の `at` が入っている日の数。数えるのは、ドライブの `feed_log.json` の記録と、この端末の未送信の記録を合わせたもの（同じ記録は 1 つと数える）。見送りは数えない
  - `feed_log.json` は一覧を読み込むときに一緒に読む（無ければ 0）。読めなくても一覧は出す

### 5. 端末の中の表示の重ね合わせ

- 入れた・見送った・取り消した結果は、押した直後から表示に出す。papers.json が追いつくまで（その論文の `pdf` が埋まる／`skipped` が一致する）、または送信済みで 24 時間たつまで、端末の記録を優先する（読了の上書きと同じ考え方。`js/reading.mjs` の今の作りに合わせる）
- 端末に覚えるものは `paper-reader-v1` の中に足す

### 6. 朝の合図の手順（README）

`README.md` に「朝の合図（iPhone のショートカット）」の節を足す。本人が iPhone で 1 回だけ設定する手順:
ショートカット → オートメーション → 新規 →「時刻」（毎日・好きな時刻）→「すぐに実行」→ アクション「通知を表示」（本文例「今日の一本が届いています」）。通知を押してもアプリは開かないので、ホーム画面の論文リーダーから開く（本人の決定: 開くのは自分のタイミング）。

## 不可侵（壊してはいけないもの）

- ドライブで**作ってよいのは** `survey/` 直下の PDF（`pdf_name` の名前で、同名が無いときだけ）と `_reader/feed_log.json`、**更新してよいのは** `_reader/feed_log.json` と `_reader/reading_log.json` だけ。既存の PDF・papers.json・ほかのファイルを書き換えない・消さない・名前を変えない
- `feed_log.json` の過去の行を消さない・書き換えない（追記だけ）
- 段階 1・読了ボタン・絞り込み・読了の上書きの受け入れ条件と、デモの動き
- `localStorage` のキー `paper-reader-v1` の名前と今の保存内容（足すだけ）

- `fetch` は普通の関数として呼ぶ（`this.fetcher(...)` にしない。iPhone の Safari が止まる。`js/drive.mjs` の今の書き方を守る）

## 制約

- 依存: 追加なし
- デモ（`?demo=1`）ではドライブに書かない。デモの `papers.json` に `feed` を足す（今日の一本・PDF 待ち 2 本・PDF 入り 1 本・見送り 1 本。日付はデモを開いた日から数えて決める）。デモの「PDF を入れる」は選んだファイルを端末の中だけで開く（`URL.createObjectURL`）。**デモの論文・要約は作り物にする**（本物の論文の題・要約をリポジトリに入れない）。`scripts/generate-demo.py` を使っているなら、そちらも合わせる
- Service Worker を変えたらキャッシュ名を上げる（今の名前から 1 つ）
- 範囲外: メモ欄（次のブリーフ）／Notion の API を呼ぶこと／PDF を自動で取ってくること／オフラインの PDF／Web プッシュの通知／Mac 側の `export_reader.py`（WorkSpace の仕事）

## エッジ / 落とし穴

- 日付は日本時間で決める（UTC だと朝 9 時前に前の日になる）
- PDF は数十 MB になることがある。中身を `localStorage` に入れない
- アップロードの途中でアプリを閉じたら、途中のものは捨ててよい（次に開いたとき、同名が `survey/` にあるかを先に調べるので二重にならない）
- 同じ論文で「入れる」を 2 回押されても、2 つ目は同名があるので上げない
- Drive は同じ名前のファイルを複数持てる。同名を探すときは `survey/` 直下・ゴミ箱以外で、1 つでもあれば「ある」とする
- `pdf_name` が無い feed（Mac 側が古い）では「PDF を入れる」を出さない
