- **出典**: 本人 2026-10-24「論文を読んだら、ボタンとかで未読から読了にできるようにしてほしい。それが notion のデータベースの方とも同期してくれると最高」。要件 `/Users/kakeru/Dev/_system/docs/20261024-論文リーダー要件.md` §5 段階3（メモは今回やらない）。Mac 側の要件 `/Users/kakeru/Dev/_system/docs/20261024-論文リーダー-読了の同期要件.md`（**§3 の reading_log.json の形と §5 がアプリとの取り決め**。必ず読む）
- **委任設定**: effort=`high` / model=既定（初めてドライブに書く。権限・失敗・端末内の表示の重ね合わせが絡むため）

## 目的

読んだ論文を、読む画面のボタン 1 つで「読了」にできる。押した直後から一覧と画面に反映され、Mac が 30 分ごとに Notion の Read Status に戻す。

## 作るもの（WHAT）

### 1. ボタン

- 読む画面の上の帯（横持ち・縦持ちの両方で、シートを開かなくても見える場所）に、今の状態に応じて「読了にする」か「未読に戻す」のボタンを 1 つ置く。押したら即座に表示が切り替わる
- 縦持ち（390px 幅）でも、一覧へ戻る・題・このボタン・情報を開く が重ならず、題は省略記号で縮む
- 基本情報タブの Read Status と、一覧の行の Read Status も同じ値を出す
- 一覧の並び（未読が先）も、押した結果で並び直す

### 2. ドライブへの記録

- 押すたびに、`survey/_reader/reading_log.json` に 1 行追記する。形は Mac 側の要件 §3 のとおり（`{"events": [{"id", "read_status": "読了"|"未読", "at"}]}`。`at` は ISO 8601・`+09:00`）
- ファイルが無ければアプリが作る（`_reader/` フォルダの中に、`application/json` で）。あれば中身を読んで末尾に足し、同じファイルを上書きする（ファイル ID は変えない）
- 書き込みには OAuth のスコープ `https://www.googleapis.com/auth/drive.file` を**足す**（`drive.readonly` と両方を要求する）。`drive.file` はアプリが作ったファイルしか書けないので、ほかのファイルは今までどおり読むだけ
- すでにログインしている本人のトークンには `drive.file` が無い。書き込みで 403（権限不足）が返ったら、「読了を記録するには、もう一度ログインして書き込みを許可してください」と出してログインし直せるようにする（勝手にリダイレクトしない）
- 送れなかった記録（通信なし・ログイン切れ・権限不足）は端末に残し、次に開いたとき・ログインし直したとき・通信が戻ったとき（`online`）に、古い順に送り直す。送れたものから消す。送れていない件数があれば、設定画面に「未送信の記録: n 件」と出す
- デモ（`?demo=1`）ではドライブに書かず、端末の中だけで切り替わる

### 3. 端末の中の表示の重ね合わせ

- Mac が Notion に戻して papers.json を書き出し直すまで、papers.json の `read_status` は古いまま。そこで、端末に「この論文をいつ何にしたか」を覚え、**押した時刻が papers.json の `generated` より新しいものは、端末の値で上書きして表示する**。`generated` の方が新しくなったら、papers.json の値を正とし、端末の記録は消してよい

## 不可侵（壊してはいけないもの）

- ドライブで書いてよいのは `_reader/reading_log.json` だけ。PDF・papers.json・ほかのファイルを書かない・消さない・名前を変えない
- `reading_log.json` の過去の行を消さない・書き換えない（追記だけ）
- 段階1の受け入れ条件（一覧・PDF・要約・基本情報・境目・ページの記憶・ピンチ）と、デモの動き
- `localStorage` のキー `paper-reader-v1` の名前と、今の保存内容（既存の値は読めるまま。足すだけ）
- `fetch` は必ず普通の関数として呼ぶ（`this.fetcher(...)` にしない。iPhone の Safari が止まる。`js/drive.mjs` の今の書き方を守る）

## 制約

- 依存: 追加なし
- 書き込みは Drive API v3 の作成（`POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart`）と更新（`PATCH https://www.googleapis.com/upload/drive/v3/files/<id>?uploadType=media`）だけ
- Service Worker を変えたらキャッシュ名を上げる（今 `paper-reader-shell-v2`）
- 範囲外: メモ／Notion の API を呼ぶこと（Mac 側の仕事）／`reading_log.json` を消す・まとめる仕組み／今日の一本・オフラインの PDF（段階2）／Read Status の「未読」「読了」以外の値

## エッジ / 落とし穴

- 同じ論文を短い間に何度も押したら、押した順にすべて追記する（Mac 側は `at` が一番新しいものを使う）
- 送り直しの途中で別の押下があっても、行が抜けたり 2 回送られたりしない（1 度に 1 つずつ送る）
- `reading_log.json` が壊れていて読めないとき（JSON でない）は、上書きせずに送信を止め、設定画面に理由を出す（過去の行を消さないため）
- 端末に覚える押下の記録は `paper-reader-v1` の中に入れる
- ログインし直しで、開いている論文・読んでいるページを失わない（段階1の「期限切れでも表示は消さない」と同じ）
