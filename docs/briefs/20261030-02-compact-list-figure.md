> 種別: 機能追加（中）。Claude が作成し Codex に渡す実装仕様。

- **プロジェクト**: `/Users/kakeru/Dev/4_アプリ/PaperReader`

- **Mac 側の依頼**: `/Users/kakeru/Dev/_system/docs/20261030-論文リーダー-Figure1要件.md`（`papers[].figure` と `_reader/figures/` の形。**§2 が正**）。アプリはそれを待たずに作れる（`figure` が無い papers.json でも動くこと）
- **委任設定**: effort=`high` / model=既定

## 目的

132 本ある一覧を、縦持ちで 1 画面に 6〜7 本（今は 2 本弱）見えるようにする。各行の左に Figure 1 の小さな画像を出し、題を読まなくても何の論文か分かるようにする。

## 作るもの（WHAT）

### 1. 一覧の行（今のカードを置き換える）

1 本の論文 = 1 行。左に画像、右に文字。行全体を押すと今までどおり論文を開く。

```
┌────────┬──────────────────────────────┐
│ [図]   │ 和題（1 行で切る）     ★★★★ 既読 │
│        │ 英題（1 行で切る・薄い色）      │
│        │ 著者（1 行で切る・薄い色）      │
│        │ コメント（1 行で切る）          │
└────────┴──────────────────────────────┘
```

- **画像の枠**: 幅 88px・高さ 66px くらい（4:3）。画像は `object-fit: contain` で枠に収め、背景は薄い灰色。画像が無い・まだ読めない・読めなかった論文は、同じ大きさの枠に和題の最初の 1 文字か「図なし」を出す（行の高さが変わらないこと）
- **文字**: 和題（空なら英題）を 1 行目に太字で。2 行目に英題（和題が空なら出さない）。3 行目に著者（空なら出さない）。4 行目にコメント（空なら出さない）。どれも 1 行で「…」に切る。コメントは今の「コメント」の印か色で、著者と見分けがつくようにする
- **右上**: ★ と読了の状態（「既読」など今の `read_status` の文字）。「PDF なし」も今の条件で小さく出す
- **タグ**: 行には出さない（絞り込みのタグの列は今のまま残る）。年・会場も行には出さない（論文の画面の「基本情報」で見る）
- **行の高さ**: 4 行すべてあっても 1 行 96px 前後に収める（390×844 の縦持ちで、一覧の部分に 6 本以上見える）
- **横持ち**: 一覧の幅が 700px 以上なら 2 列に並べる（並び順は左上 → 右上 → 左下 …）。700px 未満は 1 列
- 今の `.paper-card` の形（大きいカード・コメント 3 行）はやめる。切り替えは作らない

### 2. Figure 1 の画像を読む

- papers.json の `papers[].figure` が `{name, drive_id}` のとき、ドライブの `files/<drive_id>?alt=media` で画像を読み、`URL.createObjectURL` で表示する。`figure` が無い・`null`・`drive_id` が空なら読まない（画像なしの枠）
- **見えている行だけ読む**: `IntersectionObserver`（少し先まで、例: `rootMargin: 300px`）で、画面に近づいた行の画像だけ読む。132 本を一度に読まない。同時に読むのは 4 本まで
- 読んだ画像は、そのページを開いている間だけメモリに持つ（`Map` の id → オブジェクト URL）。一覧を描き直しても読み直さない。**端末に保存しない**（`localStorage` にも Cache Storage にも入れない。Service Worker は Google のドメインをキャッシュしない決まりのまま）
- 読めなかった（404・403・通信の失敗）ら、その行は画像なしの枠のまま。エラーを画面に出さない（一覧の邪魔をしない）。404 はそのページの間は読み直さない。「再読み込み」で papers.json を読み直したら、`drive_id` が変わった論文だけ読み直す
- ログインしていない・デモでないときに画像のために新しいログインを求めない（papers.json が読めているならトークンはある）

### 3. デモ

- `demo/figures/` に作り物の画像を置く（架空の図。単純な図形や色の組み合わせで、論文ごとに見分けがつくもの。PNG か JPEG・1 枚 40KB 以下）。`scripts/generate-demo.py` で作れるなら合わせる（依存は足さない。SVG を書いて画像にする手段が無ければ、手で作った小さな画像を置いてよい）
- デモの `papers.json` のおよそ 3 分の 2 に `figure`（`drive_id` は `demo:<ファイル名>` のように、デモだとわかる値）を入れ、残りは `null` か項目なし。デモでは `../demo/figures/<name>` を読む
- 縦長の図・横長の図を 1 枚ずつ混ぜる（`contain` で収まるかを見るため）

## 不可侵

- 前のブリーフまでの受け入れ条件（`docs/briefs/` の 20261024〜20261030-01）。特に、並び 4 つ・絞り込みと検索・読了の上書き・コメントの編集と同期・今日の一本と PDF 待ち（5 本）・n/7
- 一覧の上の「今日の一本」と「PDF 待ち」の見た目は変えない（今回は論文の一覧の行だけ）
- `localStorage` のキー `paper-reader-v1`。足すものは無い（画像は保存しない）
- `fetch` は普通の関数として呼ぶ（Safari の不具合 `fc1be99`）
- papers.json の形は変えない。`figure` が**無い** papers.json（今の本物）を読んでも落ちない

## 制約

- 依存: 追加なし
- ドライブへの書き込みは増やさない（画像は読むだけ。スコープも変えない）
- 390px 幅・844px 幅で行がはみ出さない。長い和題・英題・著者・コメントは必ず 1 行で切れる
- Service Worker を変えたらキャッシュ名を上げる
- 範囲外: Mac 側の画像づくり／フィードの論文の画像／論文の画面に図を出すこと／表の形／形の切り替え
