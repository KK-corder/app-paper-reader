## 目的

本人が iPhone を横に持ち、左で PDF を自由にスクロール・拡大しながら、右で要約と基本情報を読めるようにする。今の「今日の一本」はリマインダーにタイトルと要約が届くだけで PDF が横に無く、読まれていない。段階1は「読むだけ」。本人が数日使ってから段階2（今日の一本・オフライン）へ進む。

## 作るもの（WHAT）

App Store に出さない PWA（形のお手本は `/Users/kakeru/Dev/4_アプリ/KusuriLogWeb/`。ビルドなしの素の HTML・CSS・JS）。GitHub Pages（`https://kk-corder.github.io/app-paper-reader/`）で配信し、Safari でホーム画面に追加して使う。サーバーは置かない。

### 1. データの読み込み（Google ドライブ）

- 本人の Google アカウントで OAuth 2.0 のアクセストークンを得て、Drive API v3 で読む。スコープは `https://www.googleapis.com/auth/drive.readonly` だけ
- ログインの方式を 2 つ用意し、設定画面で切り替えられるようにする（iPhone のホーム画面版で、どちらが戻ってこられるかが実機でしか分からないため。`docs/decisions.md` 2026-10-24）
  - **リダイレクト（既定）**: 同じ画面のまま `https://accounts.google.com/o/oauth2/v2/auth` へ移り（`response_type=token`、`state` を付ける）、アプリの URL に戻ってきた `#access_token=…` を読む。`state` が一致しなければ捨てる。読んだら URL からトークンを消す（`history.replaceState`）
  - **ポップアップ**: Google Identity Services（`https://accounts.google.com/gsi/client`）の `initTokenClient`。このスクリプトはポップアップの方式を選んだときだけ読み込む
- トークンは有効期限ごと端末に保存し、期限内に開き直したらログインし直さない。期限切れや 401 のときは「もう一度ログイン」の画面を出す（勝手に何度もリダイレクトしない）
- `papers.json` の場所: マイドライブからのフォルダの道筋（既定 `University/01_reaserch/survey`。`01_reaserch` の綴りはそのまま）の下の `_reader/papers.json`。道筋は設定画面で変えられる。フォルダは名前でたどり、見つけた ID は端末に覚えておく
- PDF: `pdf.drive_id` があればその ID、無ければ survey フォルダの中を `pdf.name` で探す（要件 §4）。PDF は `files/<id>?alt=media` を Authorization ヘッダー付きで読む
- OAuth のクライアント ID は `config.js` に置く（秘密ではない値。今はまだ無いので空文字にしておき、空のときはログインの画面に「config.js にクライアント ID を入れる」と出す）

### 2. 一覧画面

- `papers.json` の論文を、未読（`read_status` が「未読」）を先に、その中で `importance` の ★ の数が多い順に並べる。同じなら題の順
- 各行: 題・和題・年・会場・タグ・Importance・Read Status。PDF が無い論文（`pdf` が null、`pdf.name` が空、または探して見つからない）は「PDF なし」と表示する
- 上に絞り込みの入力欄。題・和題・タグのどれかに入力した文字を含むものだけを残す（大文字小文字を区別しない）
- 右上に再読み込み（`papers.json` を取り直す）と設定。`papers.json` の `generated` を「いつの書き出しか」として小さく出す
- 「今日の一本」（`today`）は段階2で扱う。段階1では一覧に特別な表示をしない

### 3. 読む画面

- **横持ち**: 左に PDF、右に情報パネル。境目をドラッグすると幅が変わる（左が画面の 25%〜75% の範囲）。幅は端末に覚え、次に開いたときも同じ
- **縦持ち**: PDF を全面に出し、情報パネルは下からのシートで開閉する（ボタンで出し入れ。シートの中でもタブで要約・基本情報を切り替える）
- iPhone のノッチ・ホームバーに文字や操作がかからないようにする（横持ちでは左右、縦持ちでは上下の安全領域）
- 左上に一覧へ戻るボタン
- **PDF**（pdf.js で描画。§制約）
  - 全ページを縦に並べ、指で縦に自由にスクロールできる。見えているあたりのページだけを描画する（124 本のうち最大 約 105MB・数十ページの PDF がある）
  - ピンチで拡大・縮小できる（PDF の領域だけ。画面全体は拡大しない）。指を離したら、その倍率でくっきり描き直す。倍率は 0.5〜4 倍
  - 今いるページを「3 / 12」の形で表示する
  - 開いたページを論文ごとに端末へ覚え、次にその論文を開いたらそのページから表示する
  - 読み込み中は進み具合（読めればバイト数か %）を出す。失敗したら理由（ログイン切れ・見つからない・読めない PDF）を出す
  - PDF が無い論文は、PDF の領域に「PDF なし」と出し、情報パネルは普通に読める
- **情報パネル**: タブで切り替える
  - **要約**: `summary` の配列の順に、見出し（`heading`）と本文（`text`）。本文の改行はそのまま改行にする。要件 §2 の見出しの順（新規性と貢献（一言）〜本研究の限界）は書き出し側がそろえるので、PWA は並べ替えない。`summary` が空なら「要約なし」
  - **基本情報**: 題・和題・著者・年・会場・Type・DOI（`https://doi.org/<doi>` へのリンク。新しいタブで開く）・タグ・Importance・Read Status・BibTeX（そのまま表示し、コピーボタンでクリップボードへ。コピーできたら「コピーしました」）。空の項目は「—」

### 4. 設定画面

- ログイン状態（ログイン中／していない）・ログイン・ログアウト（端末のトークンを消す）
- ログインの方式（リダイレクト／ポップアップ）
- survey フォルダの道筋

### 5. デモの状態（確認用）

- `?demo=1` で開くと、ログインも Drive も使わずに `demo/papers.json` と `demo/*.pdf` を読む。画面と操作は本番と同じ
- デモのデータは**作り物**にする（本人の論文の題・要約・PDF を入れない。要件 §7）。論文 4 本以上: 未読と既読・★ の数の違い・PDF なし・要約なし・長い題・長い要約を含める。PDF は 12 ページ以上で、ページごとに大きくページ番号が入っているもの（スクロールと「3 / 12」の表示と拡大を確かめるため）。PDF を作るスクリプトを置くなら、依存を足さずに書く

### 6. PWA

- `manifest.webmanifest`（`display: standalone`、向きの固定なし、日本語名「論文リーダー」）とアイコン
- Service Worker はアプリの殻（HTML・CSS・JS・pdf.js・アイコン）だけをキャッシュする。**Google のドメイン（`googleapis.com`・`accounts.google.com` など）への通信はキャッシュしない・横取りしない**（段階1では PDF も `papers.json` も端末に溜めない）

## 制約

- 依存: **pdf.js（`pdfjs-dist@4.10.38` の legacy の build）だけを `vendor/pdfjs/` に同梱する**（本人 2026-10-24 了承。Claude が `vendor/pdfjs/` に置いてから渡す。置いた中身は変えない）。ほかの依存・CDN・ビルドの仕組みは足さない。Google Identity Services のスクリプトは「ポップアップ」を選んだときだけ Google から読む

- 文字は `textContent` で入れる（`papers.json` の文字列を HTML として解釈しない）
- 対象環境: iPhone の Safari とホーム画面版（iOS 17 以降）。確認は Mac の Chrome のスマホ表示でも行う
- **範囲外**: 今日の一本の表示・オフラインで PDF を開く（段階2）／「読んだ」ボタン・メモ・Drive への書き込み（段階3）／`papers.json` を書き出すスクリプト（WorkSpace 側）／GitHub のリポジトリ作成・push・Pages の設定（本人に確かめてから Claude が行う）／Google Cloud の設定（本人が行う）／PDF への書き込み・注釈・本文の検索

## エッジ / 落とし穴

- **iPhone のホーム画面版の OAuth**: ホーム画面版から Google のログインへ移ると、Safari の別画面に渡されて戻ってこないことがある（報告例あり。iOS の版で違う）。だから方式を 2 つ持ち、どちらでも失敗したときに「Safari のタブで開けば読める」ことを壊さない（普通の Safari のタブでも全部動くこと）
- Drive の `alt=media` は Range の読み込みに対応する。大きい PDF を全部読み終わるまで待たずに最初のページを出せるとよいが、Range で失敗したら丸ごと読み直す（Range が使えるかは実機で確かめる。使えなくても動くこと）
- アクセストークンは約 1 時間で切れる（リフレッシュトークンは無い）。読んでいる途中で切れても、表示済みの PDF・要約は消さない
- pdf.js の worker は `vendor/pdfjs/` の中のものを指す（CDN を指さない）。GitHub Pages ではサブパス（`/app-paper-reader/`）で配信されるので、パスは相対で書く
- 画面全体のピンチ拡大を止めると、iOS の Safari が設定によって無視することがある。PDF の領域でジェスチャーを受け、`touch-action` などで画面全体が動かないようにする
- 横持ちで iPhone のアドレスバー・ホームバーが出入りしても、PDF と情報パネルの高さが画面に収まる（`100vh` ではなく動的な高さ）
- `papers.json` の `importance` は「★★★★」のような文字列（★ の数で比べる）。`year` は数か null
- 同じ名前のフォルダが複数あるときは、最初に見つかったものを使い、設定画面に使っているフォルダの ID を出す
